ANIME VOID 17.0 — МАСТЕРСКАЯ ПРОФИЛЯ

Готовое совмещённое обновление поверх AV 16.7.
Карта вселенных, звуки 16.6 и существующие функции сохранены.
Публикация на GitHub не выполнялась. Реальные деньги не списывались.

1. ОБЫЧНАЯ УСТАНОВКА САЙТА

Рекомендуется сначала экспортировать обычный бэкап прогресса на сайте.
Распакуй ZIP. Скопируй содержимое в корень проекта AV, где лежит index.html.
Подтверди замену файлов и объединение папок audio и studio.
Остальные файлы проекта НЕ удаляй. Это не полный репозиторий с нуля.
В VS Code: Source Control → Commit → Sync Changes.
Дождись публикации Pages, затем Ctrl+F5. Установленную PWA полностью закрой
и открой снова после первого открытия обновлённого сайта с интернетом.
НЕ очищай данные сайта/localStorage — это не требуется.

2. ГДЕ НОВЫЙ ПРОФИЛЬ

Открой «Профиль» → «Оформление и магазин».
В мастерской: Магазин / Инвентарь / Награды / История.
Есть поиск, категории и предпросмотр без списания валюты.

38 позиций: 9 фонов, 9 баннеров, 8 рамок, 4 варианта эффектов и 8 наборов.
В это число входят бесплатные базовые варианты и закрытая рамка автора.
Фоны/баннеры — оригинальные локальные SVG-сцены: космос, неоновый город,
сакура, святилище, лес, лунный берег, сияние и библиотека.
Авторская рамка доступна только аккаунту автора через настройку сервера.

3. ОСКОЛКИ — РАБОТАЮТ СРАЗУ, БЕЗ СЕРВЕРА

Нажми «Забрать доступные награды».
Новая для начислений отметка серии: 2 осколка, максимум 200 за сутки UTC.
Каждое из 40 существующих достижений даёт бонус один раз.
Старый прогресс тоже учитывается. Необработанные из-за дневного лимита серии
можно забрать в другой день. Снятие и возврат отметки не дают вторую награду.

Сайт учитывает отметки трекера, а не доказывает просмотр видео.
Осколки не выводятся в деньги и не переводятся пользователям.
Рамки/эффекты с условием открываются после указанного прогресса.
Покупка не включает оформление сама: найди его в инвентаре → «Применить».
Анимации профиля можно выключить; системное уменьшение движения учитывается.

Локальные монеты/инвентарь/настройки входят в обычный бэкап AV.
При объединении бэкапов инвентарь и список учтённых наград объединяются;
баланс и настройки берутся из импортированного файла. Балансы не суммируются.
Локальную экономику, как любые данные в браузере, нельзя считать защищённой
от ручного редактирования владельцем браузера. Она НЕ даёт серверных платных прав.

4. РЕАЛЬНЫЕ ДЕНЬГИ — КОД ГОТОВ, ПОДКЛЮЧЕНИЕ ОТДЕЛЬНО

В backend находится сервер аккаунтов, баланса/прав и интеграции ЮKassa.
Это не просто ссылка на донат и не выдача предмета по кнопке «я оплатил».
Предмет за рубли выдаётся только после проверки платежа сервером через API.

Сейчас apiBase пустой, реальные платежи выключены. Нужны:
• отдельный HTTPS-сервер с постоянной базой;
• подходящий подтверждённый магазин ЮKassa и его ключи;
• условия продажи, конфиденциальность, возвраты, поддержка и корректные чеки;
• проверка собственного тестового магазина и независимый security review перед live.

Полная инструкция: backend/README.md.
Стартовые цены и ассортимент: profile-catalog.json; на сервере должен быть
тот же каталог, что на сайте. При изменении цен сверяй оба экземпляра.
Для кассы используются серверные цены, не присланные клиентом значения.

НЕ вставляй ключ ЮKassa в studio-config.js, GitHub, чат или HTML.
В studio-config.js указывается только публичный URL своего API после развёртывания.
Не публикуй .env, SQLite-базу, сессии, recovery-коды и серверные бэкапы.
Папка backend в архиве содержит только исходники/примеры, без настоящих секретов.

Локальный профиль и аккаунт — два независимых инвентаря. Локальные покупки
не становятся платными/серверными при входе. Прогресс аккаунта для наград
обрабатывается сервером отдельно. Сам трекер пока не синхронизируется через аккаунт.
Для серверного оформления нужен доступный API; офлайн показывается локальный профиль.

Автор: создай аккаунт на настроенном сервере, узнай UUID через manage.py account,
впиши его в серверный OWNER_ACCOUNT_ID. После обновления аккаунта станет доступна
рамка «Автор ANIME VOID». Обычный логин «author» прав автора не даёт.

5. ЧТО ПРОВЕРЕНО

Виртуальный Chromium: 320/360/390/412/768/1440 px, в том числе 320×568.
Магазин, покупка/примерка/инвентарь, награды, 5 тем, RU/EN, бэкапы, офлайн,
отказ хранилища и сохранность старого прогресса.
Тестовая цепочка оплаты: заказ → серверная проверка → выдача → полный возврат.
Подмена цены/статуса/режима и повторные уведомления проверены на имитаторе API.
Это НЕ реальная операция ЮKassa, НЕ проверка физических телефонов и НЕ аудит безопасности.
Для настоящей оплаты сначала выполни этапы из backend/README.md.
